# Day 11：Demo 脚本 + Prompt 固化

**目标**
基于已完成的 "语音唤醒 + 连续对话 + 拍照问答" 完整链路，固化演示流程，并优化 Prompt 以适应 TTS 播报（简洁、口语化、去除 Markdown 符号）。

**交付内容**

### 1. 完整演示脚本 (Demo Script)
场景：用户手持设备，对着 TP-Link 路由器说明书进行操作。

**流程 A：唤醒即拍与问答 (Wake-to-Photo)**
1.  **唤醒**：对准说明书，说 "小帮，小帮"
2.  **自动拍摄**：设备自动拍照并上传（无感），同时开始聆听。
3.  **提问**："这个路由器怎么登录管理后台？"
4.  **回答**：基于自动拍摄的照片进行 RAG 检索回答。

**流程 B：打断与话题切换**
1.  **提问**："怎么修改 WiFi 密码？"
2.  **打断**：AI 正在回答时，用户说 "小帮，暂停"
3.  **响应**：AI 立即停止播报
4.  **追问**："算了，告诉我怎么恢复出厂设置？"
5.  **回答**：回答恢复出厂设置步骤 + **风险提示**（TTS 需重读风险）

**流程 C：混合模式 (闲聊)**
1.  **提问**："这路由器看着挺复杂的，给我讲个笑话放松下"
2.  **回答**：调用 GPT-4o-mini 进行简短闲聊

### 2. Prompt 固化 (System Prompt)
针对 TTS 播报场景优化 Prompt：
- **去结构化**：减少复杂的 Markdown 列表，改用口语化的 "第一步、第二步"。
- **去符号**：移除 `**`, `###`, `[]` 等 TTS 可能会读出来的符号。
- **风险前置**：危险操作（如 reset）必须先读警告。
- **长度控制**：单次回答尽量控制在 100 字以内，长内容引导用户追问。

### 3. TTS 播报优化
- 过滤 Markdown 符号的正则处理
- 语速与停顿调整

**验收标准**
- [ ] 唤醒率 > 90% (安静环境)
- [ ] "小帮，暂停" 响应时间 < 1秒
- [ ] RAG 回答无 "星号星号" 等怪异读音
- [ ] 风险提示清晰可辨
